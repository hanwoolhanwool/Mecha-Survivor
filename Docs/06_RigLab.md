## 1. 목적과 범위

무기 마운트(장착 모델)·총구(투사체 생성 위치)·애니메이션을 **한 씬에서 눈으로 보며 조정하고,
결과를 데이터로 저장해 본편이 그대로 쓰게 만든다.**

동기가 된 문제:

1. 트윈 로켓 캐논/레일건 마운트 위치가 **Game·CityMap 두 씬에 수동 중복** 배치돼 있다.
   수치를 바꾸려면 씬 2곳을 똑같이 고쳐야 하고, 씬이 늘수록 더 나빠진다.
2. **투사체 생성 위치가 장착 모델과 무관하다.** 플레이어 무기는 무기 프리팹의 `_muzzle`
   (플레이어 루트의 WeaponMount 기준)에서 발사되고, 적은 `EnemyBrain.cs`에
   `transform.position + Vector3.up * 1.5f`로 하드코딩돼 있다. 레일건 포신 끝에서
   빔이 나가게 하려면 조정 도구와 데이터 통로가 둘 다 없다.
3. **캐릭터(플레이어 기체)가 추가될 예정**이고, **적 로봇도 모델로 교체·관리**해야 한다.
   지금은 기체 모델이 씬에 고정 배선돼 있어 선택/교체 구조 자체가 없다.

범위에 포함: 데이터 모델(리그 프로필), 런타임 빌더, RigLab 씬 + 조정 도구, 기존 씬 마이그레이션.
범위 제외: 새 캐릭터/적 모델 제작 자체, 인게임 캐릭터 선택 UI(격납고 연동은 후속).

## 2. 현재 구조 진단

| 항목 | 현재 상태 | 문제 |
|---|---|---|
| 마운트 위치 | Game·CityMap 씬의 본(UpperChest/RightHand) 자식으로 수동 배치, `WeaponMountVisuals`가 표시/숨김 | 씬 간 중복, 조정 시 포즈 샘플링 절차 필요 |
| 마운트 모델 표시 | `WeaponMountVisuals` (슬롯 폴링) — 동작 검증 완료 | 유지 (변경 없음) |
| 플레이어 총구 | `Weapon._muzzle` Transform (무기 프리팹 내부) | 장착 모델(포신)과 무관한 위치에서 발사 |
| 적 총구 | `EnemyBrain.cs:302` 하드코딩 `up * 1.5f` | 데이터화 안 됨, 적별 차이 표현 불가 |
| 캐릭터 선택 | 없음 (MechaModel 씬 고정 배선) | 다기체 대비 구조 부재 |
| 적 모델 | 프리미티브 프리팹 5종 (Enemy_Walker 등) | 로봇 모델 교체 예정 — 교체 시 총구/애니 조정 필요 |
| 조정 도구 | 없음 (execute_code로 수동 작업) | 반복 불가능, 눈으로 확인 어려움 |

## 3. 목표 데이터 모델 — "리그 프로필"

핵심 원칙: **씬에는 아무것도 손으로 배치하지 않는다.** 조정 결과는 전부 ScriptableObject에
저장되고, 런타임 빌더가 스폰 시 재구성한다. (§2 금지사항의 SO 밸런싱 원칙과 동일 철학)

### 3.1 `RigProfileData` (신규 SO) — 캐릭터/적 공용

```
RigProfileData
├─ ModelPrefab            기체/적 모델 (FBX 프리팹)
├─ AnimatorController     확인용 AC (적은 없을 수 있음)
├─ Mounts[]               마운트 정의 목록
│   ├─ Id                 "BackWeapon", "RightHandWeapon", ...
│   ├─ Bone               HumanBodyBones (Humanoid) 또는 본 경로 문자열 (Generic 폴백)
│   ├─ LocalPosition/Rotation/Scale   본 기준 로컬 값 — RigLab이 저장하는 대상
│   └─ VisualPrefab       마운트에 붙는 무기 모델 (TwinRocketCannons 등)
└─ Muzzles[]              총구 정의 목록
    ├─ Id                 무기/공격 식별자 ("laser_cannon", "enemy_main", ...)
    ├─ MountId            기준 마운트 (""이면 모델 루트 기준)
    └─ LocalPosition/Rotation         총구 오프셋 — RigLab이 저장하는 대상
```

- **본 지정은 HumanBodyBones 우선** (Humanoid 아바타면 이름 독립). 적 로봇이 Generic이면
  본 경로 문자열로 폴백. 두 방식 모두 순수 함수 `RigProfileMath.ResolveBone`으로 분리해
  EditMode 테스트 대상으로 만든다.
- 무기↔마운트 표시 바인딩(`WeaponData` ↔ Mount.Id)은 기존 `WeaponMountVisuals` 바인딩
  배열을 프로필로 옮긴다.

### 3.2 런타임 빌더 `RigBuilder` (신규 컴포넌트)

- 캐릭터 루트(Player)에 배치. `RigProfileData`를 받아 Awake에서 마운트 빈 오브젝트를
  본 아래 생성하고 VisualPrefab을 붙인 뒤, `WeaponMountVisuals` 바인딩을 코드로 구성.
- **Game·CityMap의 수동 마운트 오브젝트는 제거**하고 빌더 1개 + 프로필 참조로 대체.
  씬 간 불일치 문제가 원천 소멸.
- 적은 `EnemyBrain` 스폰 경로에 통합: `EnemyData`에 `RigProfile` 필드 추가(선택적),
  프로필이 있으면 모델·총구를 빌더가 구성, 없으면 기존 프리미티브 유지 (점진 이행).

### 3.3 총구 데이터의 소비자

- **플레이어**: `MechaContext.MountWeapon` 시 프로필의 Muzzle(무기 Id 매칭)을 찾아
  `Weapon._muzzle`이 가리킬 앵커 Transform을 마운트 아래 생성·주입 (`Weapon.SetMuzzle(Transform)`
  신설). 매칭 항목이 없으면 현행 동작 유지 — 기존 무기 10종은 아무것도 안 바뀐다.
- **적**: `EnemyBrain`의 하드코딩 `up * 1.5f`를 `EnemyData.MuzzleOffset`(기본값 0,1.5,0)으로
  치환. 프로필이 있으면 프로필 총구가 우선.

### 4.2 기능 블록

**① 대상 선택**
- Tab: 캐릭터 탭 ↔ 적 탭 전환. ←/→: 목록 순환. 선택 시 기존 대상 파괴 후 프로필로 재구성
  (빌더와 같은 코드 경로 — 랩에서 보는 것 = 본편에서 나오는 것 보장).
- 초기 카탈로그: 캐릭터 = Mecha 1종, 적 = 기존 프리미티브 5종 (모델 교체 대비 자리만).
- **W: 장착 무기 순환** (2026-08-07 추가). 본편에선 `WeaponMountVisuals`가 보유 무기에 맞춰
  장착 모델을 켜고 끄는데, 랩엔 그게 없어 종전에는 전 모델을 한꺼번에 켰다 — 같은 손을 쓰는
  마운트(레일건·개틀링·빔)끼리 겹쳐 그립을 볼 수 없었다. 무기를 고르면 본편과 같은 규칙으로
  하나만 남는다: `ShowForWeapon`이 그 무기인 마운트 + 무기 조건이 없는 마운트만 표시.
  - 후보 목록은 프로필의 마운트가 `ShowForWeapon`으로 지목한 무기들(등장 순서·중복 제거) —
    별도 배선이 없어 마운트를 추가하면 목록에 자동으로 들어온다.
  - **총구 앵커는 마운트의 자식**이라 같이 끄면 발사 지점이 사라진다. `Muzzle_` 접두사
    (`RigProfileMath.MuzzleNamePrefix`)로 걸러 항상 켜 둔다.
  - 장착을 바꾸면 시험 발사(F)의 대상 총구와 캐시된 시험 무기도 그 무기로 따라가고,
    사격을 켜 둔 상태면 반동 그룹도 `MechaAnimParams.GetFireGroup`으로 맞춘다.
  - 기본값은 "전체 표시"(종전 동작). 대상을 바꾸면 전체 표시로 돌아온다.
- **E: 장착 손 순환** (2026-08-08 추가) — 양손 전부 → 오른손 → 왼손. 좌우 마운트가 생기면서
  "전체 표시"만으로는 같은 무기의 좌우 모델이 겹쳐 보이기 때문이다. 무기 표시·조정 항목
  양쪽에 걸리므로, **왼손을 골라야 왼손 마운트를 조정할 수 있다.**
  - 실측 (RigProfile_Mecha, 마운트 9 + 총구 10 = 19항목): 전체/양손 19 → 전체/오른손 11 ·
    전체/왼손 11 → 개틀링·레이저 캐논·대출력 빔·산탄 캐논은 손을 고르면 각 2
    (마운트 1 + 총구 1), 미사일 포드(등 마운트, Any)는 손과 무관하게 항상 3.

### 3.4 좌우 손 마운트 (2026-08-08)

손에 드는 무기는 **오른손·왼손 마운트를 짝으로** 갖는다. 격납고 로드아웃의 둘째 무기가
왼손이 되면서(05 §10-B10) 모델도 왼손에 붙어야 하기 때문이다.

- **`MountDef.Hand` (`MountHand` = Any/Right/Left)** — 같은 무기의 좌우 마운트를 가르는
  유일한 근거다. **이게 없으면 무기 하나가 양손에 동시에 뜬다** (좌우 마운트가 같은
  `ShowForWeapon`을 지목하므로). `Any`는 손 무관(등 마운트·적) — 어느 손에 들든 표시.
- **표시 판정**: `WeaponMountVisuals`가 `slots.Has(weapon)` 대신
  `slots.HasInHand(weapon, binding.Hand)`를 본다. 손 비교는 `RigProfileMath.MatchesHand`
  (한쪽이 Any면 통과).
- **총구는 (무기 Id, 손)으로 식별한다.** 좌우 마운트가 같은 무기 Id의 총구를 하나씩 이고
  있어서 Id만으로는 사전 키가 충돌한다(나중 것이 앞 것을 덮어써 한쪽 손 총구가 통째로
  사라진다). 키는 `RigProfileMath.MuzzleKey(id, hand)` — **Any면 Id 그대로**라 기존
  프로필·적 총구는 그대로 호환된다.
  - 총구에는 손 필드를 두지 않고 **딸린 마운트에서 끌어온다**
    (`ResolveMuzzleHand`) — 총구는 마운트의 자식이라 손이 갈릴 수 없고, 두 곳에 적으면
    어긋날 여지만 생긴다.
  - 조회 `RigBuilder.TryGetMuzzle(id, hand, out)`는 **그 손 → 손 무관 → 오른손 → 왼손**
    순으로 떨어진다. 폴백이 있어야 한쪽 손 마운트만 있는 무기를 반대 손에 들어도
    발사 지점이 남는다.
- **★ MechaContext.MountWeapon의 순서**: 총구 주입은 반드시 `WeaponSlots.Equip` **뒤**다 —
  슬롯이 손을 정하고, 총구는 손별로 다르다. 순서를 되돌리면 왼손 무기가 오른손 총구에서 나간다.
- **왼손 값은 손으로 맞추지 않았다 (미러 자동 산출)**: 오른손 마운트/총구의 월드 트랜스폼을
  기체 좌우(캐릭터 로컬 X=0 평면)로 미러해 왼손 본 로컬로 환산했다. **음수 스케일을 쓰지 않아**
  노멀이 뒤집히지 않는다.
  이 리그의 손 본은 서로 정확한 미러라(`RightHand (0.4039,…)` / `LeftHand (−0.4039,…)`)
  마운트 로컬 위치는 좌우가 **같은 값**이 되고 회전만 달라진다.

- **★★ 어느 축을 뒤집느냐가 전부다 (2026-08-08 실제 사고)**: 물체를 음수 스케일 없이
  미러하려면 로컬 축 3개 중 **정확히 하나를 뒤집어야** 한다(안 그러면 왼손 좌표계 = 부적절 회전).
  뒤집을 축은 **그 물체의 좌우 대칭면 법선** — 뒤집어도 안 보이는 축이다.
  - **마운트(모델)**: 이 프로젝트 무기 모델은 **포신 = 로컬 +X, 위 = +Y, 대칭면 법선 = +Z**.
    → `LookRotation(−mirror(forward), mirror(up))` = **로컬 Z를 뒤집는다.**
  - **총구**: 의미축이 발사 방향(로컬 +Z)이라 뒤집을 축이 다르다.
    → `LookRotation(mirror(forward), mirror(up))` = 로컬 X를 뒤집는다.
  - **사고 내용**: 처음엔 마운트에도 총구 공식을 써서 **포신축(+X)이 반대로 뒤집혔다**
    — 무기를 거꾸로 든 채로 **위치·발사 방향 검사는 전부 통과**했다(총구는 별도로 미러해서
    올바랐기 때문). 육안 판정도 좌우 조명 차이 때문에 헷갈렸다.
  - **판정 방법 (재현 가능)**: 모델 정점을 격자 해시에 넣고 축별 평면 대칭 잔차를 재되,
    **그 축의 길이로 정규화**한다(정규화 안 하면 제일 얇은 축이 무조건 이긴다).
    실측 — GatlingGunUnit Y 2.5% / **Z 0.79%**, AzureCoreCannon Y 5.4% / **Z 2.4%**
    → 대칭면 법선 = Z. (LuminaRailgun은 납작한 판이라 Y 3.8% / Z 4.2%로 무의미 — 다른 두
    모델이 같은 마운트 회전을 공유하므로 규약을 따른다.)
    ShotgunCannon(2026-08-08 추가)도 같은 판정에서 X 78.9% / Y 64.6% / **Z 27.0%**로
    Z가 최소 — 규약대로 포신 +X / 위 +Y / 대칭면 법선 +Z다. (셀 0.02·정점 1/3 표본이라
    절대 수치는 위 두 모델과 직접 비교할 수 없고, 축 사이 대소만 의미가 있다.)
  - 검증(바인드 포즈, 좌우 손이 정확한 미러인 유일한 포즈): 마운트 위치 오차 **0.000000** /
    **포신축 미러 내적 1.000001** / 위쪽 1.000000, 총구 위치 오차 0.000000 / 발사 방향 1.000001.
    **애니메이션 포즈로 비교하면 안 된다** — HeroIdle 같은 사수 스탠스는 좌우 비대칭이라
    양손의 결과가 달라 보이는 게 정상이다.
- 현행 짝: `RightHandWeapon↔LeftHandWeapon`(레이저 캐논) / `RightHandGatling↔LeftHandGatling`
  / `RightHandBeam↔LeftHandBeam` / `RightHandShotgun↔LeftHandShotgun`(산탄 캐논).
  등 마운트(`BackWeapon`)는 Any 유지.
- 가드: `RigProfileAssetTests` — 손 본 마운트의 `Hand` 선언, 오른손 마운트마다 짝 존재
  (모델·무기·스케일 동일), 총구 키 중복 없음, 그리고
  **`HandMountPairs_MirrorBarrelAndUpAxes`**: 모델을 바인드 포즈로 띄워 `RigBuilder`로 앵커를
  세우고 **포신축·위축이 실제로 미러인지** 검사한다. 로컬 수치만 보는 가드로는 위 사고를
  못 잡는다 — 이 테스트가 그 자리를 메운다.

**② 마운트 조정**
- [ / ] 로 마운트 순환 선택. 선택 마운트에 기즈모(축 표시) + HUD에 로컬 수치 표기.
- **조정 항목은 장착 무기 것만 나온다** (2026-08-08 추가). 무기를 고르면 다른 무기의
  마운트·총구는 화면에 모델도 없어서 **만져도 보이지 않는다** — 목록에 남겨 두면 엉뚱한
  항목을 조정하게 된다. 전체 표시(장착 −1)에서는 종전대로 전부 나온다.
  - 판정은 순수 함수 2개: 마운트는 기존 `RigLabMath.ShouldShowMount`(모델 표시 규칙 그대로),
    총구는 신설 `RigLabMath.ShouldShowMuzzle(muzzleId, ownerMountWeaponId, equippedId)`.
  - **총구 규칙이 세 갈래인 이유**: ① 전체 표시면 전부 ② 장착 무기 자신의 총구는 무조건
    (마운트 없이 모델 루트에서 쏘는 무기 대비) ③ 그 외에는 **달려 있는 마운트가 보이는가**를
    따른다 — 등 마운트처럼 한 마운트를 여러 무기가 공유하면(`missile_pod`/`twin_rocket`)
    모델이 보이는 동안 형제 총구도 만질 수 있어야 조정이 막히지 않는다.
    마운트가 없거나 무기 조건이 없는 마운트의 총구는 항상 보인다(걸러내면 조정 방법이 사라진다).
  - `[ ]` 순환도 걸러낸 목록을 따른다 — 패널에 없는 항목이 선택되면 기즈모만 뜨고 목록엔 없다.
    장착을 바꿔서 현재 선택이 걸러지면 선택을 자동 해제한다.
  - **저장·dirty 검사는 여전히 프로필 전체를 훑는다.** 숨은 항목의 값도 그대로 지켜야 한다.
  - 실측 (RigProfile_Mecha): 전체 9개 → 미사일 포드 3(등 마운트+총구 2) /
    레이저 캐논·개틀링·대출력 빔 각 2.
- 조정은 **씬 뷰 핸들 병용**: Play 중 씬 뷰에서 마운트 Transform을 직접 끌면 되고,
  게임 뷰만 쓸 때를 위해 핫키 넛지(화살표+PgUp/Dn 이동, Shift=회전, Ctrl=미세)를 제공.
- R: 프로필 값으로 리셋.

**③ 총구 조정**
- 마운트와 같은 조작으로 총구 앵커 이동. 총구엔 구체+전방 화살표 기즈모.
- **F: 시험 발사** — 실제 투사체/빔을 총구에서 발사해 생성 위치·방향을 궤적으로 확인.
  플레이어 탭은 해당 무기 프리팹 발사 경로, 적 탭은 `EnemyData.ProjectilePrefab` 사용.

**④ 애니메이션 확인**
- 1~9: 상태 강제 재생 — FlyIdle / Fly8방 / GroundIdle / Walk8방 / Dash / Shoot(3그룹) / Hit / HitHeavy.
  (파라미터 주입은 05 문서의 드라이버 파라미터 규격을 그대로 사용)
- +/-: 재생 속도 0.1×~2×. 마운트·총구가 본을 따라 움직이는지 애니메이션 중에 확인하는 것이
  이 블록의 존재 이유다 (특히 손 마운트는 사격 자세에서 확인 필수).
- 적 탭: AC 없는 적은 스킵 표기.
- **P: 포즈 클립 순환** (2026-08-01 추가, Docs/07). AC에 없는 전시용 포즈 클립을
  `AnimationClipPlayable`로 Animator에 **직접 물려** 재생한다 — 확인용 클립 때문에
  게임용 `AC_Mecha`에 상태를 늘리지 않기 위해서다. 클립 목록은 RigLabController의
  `_poseClips` 배열(씬 인스펙터). 그래프를 파괴하면 컨트롤러 그래프로 복귀하므로
  1~5·6~8·9·0을 누르면 자동 이탈한다. `Animator.speed`는 그래프에 안 걸려서
  재생 속도는 플레이어블에 따로 준다. `OnDisable`에서 반드시 파괴(안 하면 누수 경고).

**⑤ 저장**
- S: 현재 마운트·총구 로컬 값을 선택된 `RigProfileData`에 기록 + `EditorUtility.SetDirty`
  → `AssetDatabase.SaveAssets`. **SO는 에셋이라 Play 모드 중 저장해도 유지된다** — 이
  워크플로가 성립하는 근거. 저장 코드는 `#if UNITY_EDITOR` 가드 (RigLab은 에디터 전용 씬,
  빌드 미포함 — SpawnLab과 동일 취급).
- HUD에 미저장 변경(dirty) 표시.

## 7. 알려진 함정 (설계에 선반영 + 구현 중 발견 2건 추가)

- **FBX 루트 스케일을 덮으면 안 된다** (레일건 ×100 보정) — 크기 조절은 마운트 오브젝트 담당.
  빌더도 VisualPrefab 인스턴스의 루트 트랜스폼을 건드리지 않는다.
- **에디트 모드는 FBX 눕는 포즈** — RigLab은 Play 모드 조정이 기본이므로 회피됨. 에디트 모드
  지원은 하지 않는다 (포즈 샘플링 복잡도가 이득보다 크다).
- Play 중 **씬 뷰 핸들로 조정한 값은 Stop 시 소실** — 그래서 저장(S)이 SO에 기록하는 구조.
  Stop 전 저장을 HUD dirty 표시로 상기시킨다.
- 비포커스 Play 루프 정지 — RigLab 진입 시 `Application.runInBackground = true`.
- 새 .cs 추가 후 csproj stale — `refresh_unity` 후 빌드 (CLAUDE.md §1).
- **(발견) 모델 루트 스폰 규약**: FBX 프리팹 루트에는 -90° X 회전이 박혀 있다.
  씬 배선(Game의 MechaModel)은 루트를 (0,0,0)으로 덮어 쓰므로, 빌더의 모델 스폰도
  **로컬 identity + 프리팹 스케일 유지**로 통일했다. 프리팹 로컬 TRS를 그대로 복원하면 눕는다.
  (장착 모델(VisualPrefab)은 반대로 프리팹 루트 TRS를 복원해야 한다 — 레일건 ×100 등)
- **(발견) Animator 컬링**: 게임 뷰가 실제로 렌더되지 않으면 기본 컬링 모드가 본 포즈
  갱신을 멈춰 상태 시간만 흐르고 포즈는 바인드 그대로다. RigLab은 `AlwaysAnimate` 강제.

## 8. 미결정 사항 → 결정 완료 (2026-07-30)

1. **총구 정책**: **포신 추종 채택.** 무기 총구를 마운트 모델(포신 끝)에 붙인다. 손
   애니메이션에 따라 발사 위치가 흔들리지만 조준 정확도(`MechaAimer` 별도 계산)에는
   영향 없음 — 연출상 포신 끝 발사가 자연스럽다고 판단.
2. **캐릭터 카탈로그와 격납고 연동**: **후속 작업으로 미룸.** 이번 RigLab 작업은 독립
   카탈로그 배열로 완결하고, 캐릭터 선택이 본편 기능이 되는 시점에 `LoadoutData`/격납고와
   단일 소스로 통합한다.
3. **적 로봇 모델 도입**: **이번 범위에서 제외.** 프로필 구조만 P0에서 적 대응으로
   만들고, 실제 적 모델 교체는 모델이 준비되는 별도 작업에서 결정한다.
